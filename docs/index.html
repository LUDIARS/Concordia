Concordia

複数 AI コーディングエージェント セッションの協調 / 認識 / 記録

ラテン語で 同心 / 一致 / 協調 を意味し、ローマ女神 Concordia（元老院・市民の和合の象徴）に由来する。 lock せず、各セッションが自律的に状態を共有することで重複作業や知識の分断を防ぐ LUDIARS のサービス。

TypeScript + Node 22 Hono better-sqlite3 (WAL) React 19 + Vite loopback :11111

サービスの役割

Claude Code / Gemini CLI / Codex CLI などの AI コーディングエージェントを 並行して 使うとき、 互いの作業が見えず重複・分断・取りこぼしが起きる。Concordia は repo・session・event を 1 つの SQLite に集約し、 各エージェントの hook から HTTP で報告させることでこれを解決する。

① 重複作業の検出

同じ repo を複数セッションで触っていることを検出し、worktree 分離を 提案（強制はしない）。

② ロスト検知 + 復元

セッションが落ちても heartbeat 途絶で検知し、transcript (jsonl) から最終状態を復元・引き継ぎ。

③ 終了レポート自動生成

Stop 時に LLM サマリ + 構造化集計（diff / Todo 完遂率）を自動生成。

④ 横断モニタ

全 repo / 全 host の active session・timeline・コスト・PR キューを Web / Discord / Slack で可視化。

設計指針

  • lock しない: 並行作業を前提とする。worktree 自動化は提案のみで強制しない（lock より自由度を優先）。
  • provider 中立: sessions.provider 列で agent 種別を識別。Claude Code / Codex CLI は実装済、Gemini CLI は stub。local-llm（Lictor ネイティブ）も追加済。
  • 個人データ非保管: session 内容は session_events に蓄積し 90 日で GC。transcript はパス参照のみ保持し本体は複写しない。
  • ローカル運用: loopback (127.0.0.1) bind、認証は loopback 信頼ベース（admin token は任意）。tailnet 越えは将来。
  • LUDIARS スタック準拠: TypeScript + Node 22 + Hono + better-sqlite3、frontend は React 19 + Vite + Foundation UI。
