# WebUI 画面ガイド

Concordia の WebUI はブラウザで `http://127.0.0.1:11111` (loopback) を開くと使えます。この章では、画面上部のナビゲーションに並ぶ順にすべてのページを案内します。ナビゲーションは全 17 項目のフラットな構成で、狭い画面ではよく使う 4 タブ + 「⋯」メニューに自動で折りたたまれます (クリック頻度から上位 4 つが選ばれます)。

ナビゲーションに出ない画面が 2 つあります。**セッション詳細** (`/sessions/:id`) と**レポート詳細** (`/reports/:id`) で、それぞれ一覧からのリンクで到達します。この 2 つも本章で扱います。

## Monitor — 稼働状況の全景 (`/`)

WebUI を開くと最初に表示されるトップページで、「いま誰がどこで動いているか」の全景です。上から順に、アクティブセッションを持つリポジトリの一覧 (同じリポジトリに 2 セッション以上いると警告色で `×N` が付きます)、競合中のリポジトリごとのセッションカード、「組織セッション」(本社と子会社のカードが並ぶグリッド)、マシン別の稼働数、「PC パフォーマンス」(メモリ・CPU・セッション別メモリ・上位プロセス、10 秒更新)、そしてロスト (失踪) セッションの一覧が並びます。

組織カードには稼働状態・アクティブ数・Discord / Slack の接続状態・日次トークン予算の消費状況が表示され、カード内の spawn フォームから**新しいセッションをこの画面から直接起動**できます (委託テンプレートまたはプロバイダ直指定、プロジェクト・ブランチ・worktree・初回プロンプトを指定可能)。各セッションカードには「停止」ボタンがあり、確認ダイアログの上で強制終了できます。セッションをクリックするとセッション詳細へ、「管理 →」で子会社ページへ移動します。

## セッション詳細 — 1 セッションと向き合う (`/sessions/:id`)

Monitor などからセッションを選ぶと開く画面で、1 セッションのすべてがここにあります。上から、状態バッジ・プロバイダ・リポジトリパスなどのヘッダ、「作業リポジトリ」(プロジェクトコードとブランチ)、「作業内容」(transcript の全文パネル。内部イベント (raw / tool / thinking) は折りたたまれ、読みたいときだけ展開します)、「直近の stat」(TODO・最近の編集・open PR など)、操作ボタン列、イベントログ (JSON、トグル表示) の順です。

この画面の最重要機能は画面下部に固定された「**指示を送る**」入力欄です。ここに書いた文章がそのままセッションへの追加指示として注入されます (Enter で送信、Shift+Enter で改行、最大 4000 字)。Discord のスレッドに返信するのと同じ経路です。ほかにアクティブなセッションには「停止」「stat 依頼」「rename 依頼」ボタンがあります。セッションがツール実行の許可を求めたときは「ツール実行の許可」モーダルが、選択式の質問をしたときは選択肢ボタン付きのモーダルが、この画面に現れて回答できます。終了済みセッションからは「view report →」でレポート詳細へ移動できます。

## Work — リポジトリとブランチの現況 (`/work`)

ワークスペース配下のローカルクローンをカードのグリッドで一覧します。各カードにはリポジトリ名・現在のブランチ・追加 worktree の数・アクティブセッション数 (2 以上は警告表示)・最終コミット時刻が出ます。main クローンが既定ブランチ以外にいると赤枠で警告されるので、「誰かがメインクローンのブランチを切り替えたまま放置している」がすぐ分かります。30 秒ごとに自動更新され、操作は「更新」ボタンのみ。セッションチップからセッション詳細へ飛べます。

<!-- IMAGE: Work のリポカードグリッド。worktree バッジと ⚠ 警告付きカードを含む状態 -->

## Taskflow — task md の進行盤 (`/taskflow`)

各リポジトリの task md (タスクの正本ファイル) を走査し、担当・状態・PR・CI を 1 画面に集約します。上部に「全件 / 未着手 / 担当中 / 完了 / 中止 / CI失敗 / CI待ち」のサマリタイル、下に一覧表が並びます。プロジェクトと状態で絞り込みができ、担当セッションのリンクからセッション詳細へ、PR 番号から GitHub へ飛べます。閲覧中心のページで、ここからタスクを編集することはできません。

<!-- IMAGE: Taskflow のサマリタイルと一覧表 -->

## PRs — PR キュー (`/prs`)

組織の open PR をすべて (セッション由来でないものも含めて) 表示し、CI 失敗を先頭に優先度順に並べます。「Ready (マージ可)」「In progress」「Needs review」「Merged recently」の 4 バケットに分かれ、各行に CI バッジとレビュー状態が付きます。Revisor の local PR も専用セクションに表示され、「Revisor ページを開く ↗」で Revisor 本体へ移動できます。閲覧専用で、マージ操作は Discord のリアクションや各セッションから行います。

<!-- IMAGE: PR Queue。Revisor local PR セクションと Ready / Needs review バケットが見える状態 -->

## Cost — コストと利用制限 (`/cost`)

トークン消費の観測ページです。Claude / Codex の「Provider 利用制限」(週間と日別/5 時間) の折れ線グラフ、本社 / 子会社別のトークン集計 (本日と週間)、10 分刻みの使用量推移、チャンネル別のコンテキスト占有と累積コスト、サービス横断の LLM コスト表が並びます。画面の注記にあるとおり、コストは等価 API 換算の推定値で、サブスクリプション利用時の実課金ではありません。

<!-- IMAGE: Cost の Provider 利用制限グラフと使用量推移グラフ -->

## Reports — AI 日報 (`/reports`, `/reports/:id`)

セッション終了時に自動生成される作業レポートの一覧です。1 セッション = 1 レポートで、生成時刻・所要時間・結果 (outcome) バッジ・イベント集計・要約プレビューが並びます。不要になったレポートは「delete」で削除できます。レポートを開くと詳細画面になり、イベントのカウンタと要約 (summary) の全文が読めます。詳細画面の「← session」から元のセッション詳細に戻れます。

<!-- IMAGE: Reports の一覧 (outcome バッジと要約プレビュー付き) -->

## 作業ログ — session-logs ブラウザ (`/session-logs`)

セッション終了処理 (/session-end) や引き継ぎ時に書かれた作業記録 (ワークスペースの `session-logs/` 配下の Markdown) をプロジェクト別に閲覧します。左のプロジェクト facet で絞り込み、検索欄でタイトル・見出し・抜粋を横断検索し、クリックで全文を表示します。第 5 章のトラブルシューティングで「あのとき何をしたか」を掘り返すときに最初に来る場所です。

<!-- IMAGE: 作業ログの一覧 + プロジェクト facet -->

## Skills — SKILL.md の監視 (`/skills`)

各リポジトリの `.claude/skills/concordia/SKILL.md` をフックが監視し、書き換えのたびにスナップショットを取って解析 (poison = 汚染疑い / growth = 肥大) した結果を表示します。カードをクリックすると、poison 判定の理由・履歴 (ハッシュとスコアの推移)・本文プレビューがモーダルで見られます。スキルファイルが知らないうちに書き換えられていないかの監査用です。

<!-- IMAGE: Skills のカードグリッドと、1 件のモーダル詳細 -->

## 整理 — ワークスペース掃除 (`/ws-cleanup`)

各リポジトリの worktree 掃除・既定ブランチの ff 最新化・マージ済みブランチの削除を行うページです。安全側に倒した設計で、未マージ・未コミット変更・作業中ブランチには触らず「保留」として列挙するだけ、`reset --hard` も使いません。まず「dry-run 再走査」で何が行われるかを確認し、「安全アクションを実行」で実際に掃除します。

<!-- IMAGE: ws-cleanup の dry-run 結果 (アクションと保留が色分けされた状態) -->

## 記憶整理 — メモリ/スキルの棚卸し (`/library`)

各プロジェクトの `.claude` 配下のメモリとスキルを棚卸しするページです。重複・肥大・陳腐化疑いなどのフラグ付きでブロックが一覧され、チェックして「退避を実行」すると完全削除ではなく `_archive/` へ移動して台帳に記録されます。台帳からの「復帰」も可能です。LLM による「矛盾/整理サジェスト」もありますが、提案止まりで勝手に消すことはありません。

<!-- IMAGE: 記憶整理のブロック一覧 (フラグバッジ付き) と退避バー -->

## Delegation — 委託テンプレートと実行履歴 (`/delegation`)

第 1 章 §3 の委託機能の管理画面です。上半分がテンプレート一覧表で、雇用形態カテゴリ (従業員 / フリーランサー / パートタイマー) での絞り込み、新規作成、JSON 貼り付けでの取り込み、並び替え、編集、無効化ができます。テンプレート編集ではプロバイダ (codex / codex-sdk / claude / gemini / ローカル LLM)・モデル・既定 cwd・プロンプト雛形・引数スキーマ・フォーラムタグ有無などを設定します。「invoke」を押すと引数入力パネルが開き、その場で委託を発火 (Spawn) できます。

下半分は「外注 (作業委託)」の実行状況 — 実行キュー・順番待ち・進行中カード・完了履歴 — と Recent runs の表です。進行中カードから紐付いたセッション詳細へ移動できます。同時実行の上限もこの画面で設定します。

## マニュアル — AI に渡すルールと手順書 (`/manuals`)

AI セッションに注入する統制内容を編集するページで、タブが 2 つあります。「ハーネスルール」は守らせること — allow (許可) / block (遮断) の自然文ルールをカード単位で追加・編集・無効化します (既定ルールは削除できず、無効化のみ可能です)。「Inject マニュアル」は作業のやり方 — 実装 / レビュー / 設計相談 / テスト / 雑用の 5 種別 (語彙固定) ごとに、セッションへ差し込まれる作業手順書を編集します。

## 社員 — 役職と権限の名簿 (`/staff`)

Discord / Slack から Concordia の LLM に触れたユーザの名簿です (発言すると自動登録されます)。役職 (ヒラ社員 / 管理職 / 執行役員) の変更、メモの記入、削除、そして「まだ発言していないユーザへの役職の先付け」(手動登録) ができます。画面上部には「役職と権限」の凡例があり、どの操作にどの役職が要るかを確認できます。執行役員が 1 人もいない・管理職以上が 0 人、といった危険な状態には警告バナーが出ます。

<!-- IMAGE: 社員名簿と役職・権限の凡例を開いた状態 -->

## 子会社 — 出張先 Bot とハーネス監査 (`/subsidiaries`)

2 つのセクションがあります。「ハーネス監査ログ」は、ハーネスルールによる判定 (deny / warn / allow) の履歴を、イベント種別 (判定・遮断・供給・続行・着手) で絞り込みながら見る監査画面です。「子会社 (出張先 Delegation)」は、別の Discord guild などに置く出張所 Bot の管理で、追加・編集・起動・停止、guard モデルや日次トークン予算の設定、子会社所有の委託テンプレート管理、ロック中ユーザの解除、最近の依頼の監査まで行えます。

なおページ冒頭に案内があるとおり、共通ハーネスルールの編集はマニュアルページへ移動済みです。また「子会社」(出張所 Bot) と次の「拠点」(連合) は別の概念です。

## 拠点 — マルチ拠点連合 (`/federation`)

第 1 章 §9 の連合機能の管理画面です。本社に登録された拠点 (拠点 PC 上のローカル Concordia) の一覧に、接続状態 (online / offline)・最終応答・バージョン・未配送イベント数が並びます。「拠点を登録してトークンを発行」で新しい拠点を追加すると、接続用トークンが**一度だけ**表示されます (拠点側の `CONCORDIA_FEDERATION_SITE_TOKEN` に設定します)。不要になった拠点は「失効」で切断できます。連合 listener 自体の有効化は環境変数 `CONCORDIA_FEDERATION_LISTEN=1` で行います。

## Setup — セッション側の接続ガイド (`/setup`)

AI セッションを Concordia に接続するためのセルフサービスガイドです。人間が読む説明書というより、「AI に『Concordia/setup に接続して』と指示すると、セッション自身がこのページの API を叩いてスキル本体とフック設定をダウンロードする」ための入口です。プロバイダ (claude-code / gemini-cli / codex-cli) と配置先 (ユーザレベル / リポジトリ単位) を切り替えると、対応した指示文・スキル本体・フック設定が表示されます。Windows PowerShell の文字化け対策や、プロジェクトコード一覧もここにあります。

## 設定 — サービス内設定 (`/settings`)

サービス内で変更できる設定を左メニューで 9 セクションに分けたページです。多くは保存すると即時反映されます。

- **連携**: Discord / Slack の接続設定。トークンは暗号化保存され、保存すると bot が即時再接続するためサービス再起動は不要です。ツール許可カードを Discord に出すか、transcript 中継を要約のみにするか (message optimize) もここで切り替えます。
- **モデル**: モデルカタログ。委託や spawn の `--model` で選べるモデル候補を追加・無効化します。
- **ランタイム制御**: チャット禁止 (chat-mute)・チャットルール停止のトグルと、Discord bot の start / stop / restart。
- **リアクションWF**: リアクションワークフローの ON/OFF と、絵文字 → アクションのマッピング編集。実行できるユーザが 0 人だと警告が出ます (発火できるかどうかは環境変数ではなく社員名簿の役職で決まります)。
- **ワークスペース**: workspace root と GitHub Organization。
- **コスト予算**: 日次トークン上限。超過すると命令がブロックされ、「⛔ ブロック中」バッジが出ます。
- **Lictor**: spawn 時の Lictor 起動モード (auto / dev / prod) と各パス。
- **定期実行**: 週次レビュー・脆弱性対応・カイゼンなど、内部 cron が呼ぶ委託テンプレートの差し替え。
- **Web ホスト**: Vite の allowedHosts (dev server 再起動後に反映)。

## どの画面から始めるか

日常運用の動線をまとめると次のようになります。稼働確認は Monitor から入り、気になるセッションがあればセッション詳細で会話し、終わった仕事は Reports と作業ログで振り返る。仕事を投げるなら Monitor の spawn フォームか Delegation の invoke。統制を変えたいときだけマニュアル・社員・設定に降りていく、という使い方です。次章では、もう 1 つの (そして多くの場面で主要な) 入口である Discord からの使い方を説明します。
