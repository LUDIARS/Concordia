# セッション費用の調査

期間・タイムゾーン・対象端末・ログ保存先を決める。既存集計があれば対象時刻と
重複排除の定義を照合し、差分だけ集計する。ログ全文をLLMへ渡さず、ストリーム集計する。

- Claude: message.id単位でusageを重複除去。同一応答の分割記録はoutputの最大値を使う。
- Codex: token_countの累積値をセッション内で差分化。reasoningをoutputへ二重加算しない。
- 親ログとsubagentsを別集計してから親子合算する。ファイル数、tool-use ID数、
  成功起動数、同時稼働数は別の指標。Agentのmodel省略を親と異なるモデルと推測しない。
- キャッシュ読込・作成・通常入力・出力を分ける。guardianなど付随処理を別集計する。
- API料金換算と実請求・定額枠の消費を区別する。料金が必要なら公式の現行料金を確認し、
  対象モデル・時点・仮定を残す。削除済み/他端末/期間途中の不足を明示する。

大きい親子合計から、再委譲、重複した文脈、毎回の全量再調査を調べる。
人間が依頼した仕事の増加を無駄と断定しない。削減案には既存モデル選定の再利用、
短い作業票、差分反映、機械集計を使い、品質の受入条件と比較単位を添える。
モデル単価差だけの計算は感度分析として記し、再試行増加や実測効果と混同しない。

Ccのモデル選定変更は [内部Agent契約](../../spec/feature/internal-agent-model-policy.md) を参照。
調査だけで全体設定・モデル・コンテキスト上限・並列数を変更しない。
