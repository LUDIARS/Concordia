# セッション状態の確認

Ccが注入したworkflowとstateを使う。状態が不明・古い場合は所属sessionの記録を確認する。

Goal & Go は既定 ON。直近の「残っていること」を人間の依頼・既存許可・対応する Actio task と照合し、
進められる項目は再度 GO や同じ開始確認を求めず、そのターンで実行する。列挙だけで止めない。
明示 OFF・停止指示・未回答の確認・継続上限は維持する。残件報告は新たな作業指示や許可ではない。
状態が unknown なら必要な読み取り確認から進め、成功や完了を推測しない。
審査・委託の通知待ちはそのまま維持し、同じ依頼内の独立した残件を進める。全件待機なら理由を示す。
人間判断が必要な場合だけ human-wait を記録し、通知待ちだけで人間判断待ちへ変えない。

- task-active: リンクされた Actio タスクの現状態と人間の許可範囲を照合し、実行可能なタスクを続ける。別タスクの審査待ちを重複提出しない。
- task-blocked: Actio の依存待ち・人間判断待ちを確認する。承認範囲で進められる別タスクがあれば進め、なければ判断事項を整理して明示的な人間待ちを記録する。
- delegation-wait: 子の終了通知を待つ。子の作業を重複実行・再起動しない。
- review-needed: 対象workflowの提出手順を確認する。RvはCc経由local PR、GitHubはそのprojectのPR手順。
- review-wait: 審査通知を待つ。審査中を実装停止と誤認して変更や再提出を繰り返さない。
- review-failed: 所見と失敗記録を読み、許可された範囲で修正する。マージまで許可された委託では、競合も既存変更を保って解消し、変更headを再審査へ戻す。通常のマージ許可を再質問して止めない。テストは既存の実行許可範囲に従う。
- merge-confirmation: 審査通過・対象head・既存のマージ許可を照合する。マージまで許可された委託は再確認せずworkflowの自動マージを進め、対応PRのmergedとマージコミットを確認する。マージ可のまま停止していれば進行中操作を照合し、対象PRの既存自動マージ判定を一度再開する。他PRの一括処理、ゲート回避、結果不明の再送はしない。競合はreview-failedへ戻し、明示された人間判断要求は維持する。
- reflection-needed: 対応 PR の merged とマージコミット、必要な反映、Actio の未完了タスクを照合する。予定を列挙し、進行中は GO、実行可能な作業がなければ人間判断を要約して待機する。merged だけでループやセッションを完了にしない。
- unknown: 確認できない状態を一行で伝え、既存の指示参照・task link から必要な読み取り確認を進める。workflow、成功、完了、許可を推測しない。別の確認済み残件が進められるなら継続する。

人間の未回答確認がある場合はそれを優先して待機する。ただし通常のマージ許可を既に得ている場合は同じ確認を繰り返さない。再審査後も100以上のリスクなど、明示された人間判断要求は通常のマージ許可で上書きしない。
自動確認はpush・merge・テスト・shutdownの新たな許可ではないが、既存の許可も取り消さない。委託はPR提出・Test OKだけで完了とせず、許可範囲の修正・再審査・マージ確認まで同じループで扱う。
