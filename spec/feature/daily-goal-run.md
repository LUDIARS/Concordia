# デイリーゴール自走 (WM-2)

価値: UX-CC-W9 (主)、UX-CC-W2/W3/W4。シナリオ UX-CC-S10。
方式一覧での位置づけは [work-modes](work-modes.md)。

## 何をするか

朝に人間がその日のゴールを決める。Cc はゴールごとに専用セッションを起動し、そのセッションが
ゴールへ進み続ける。人間は 1 時間ごとに届く確認カードを見て、判断が要るときだけ答える。
止まるのはゴールに到達したとき、十分にタスクをこなしたとき、人間が止めたときだけで、
時刻や進捗の停滞では止めない (2026-10-10 neco 指示)。
スクラムの計画・振り返りの儀式は持たない。日をまたぐ工程管理は WM-5 (Director 案件) に任せる。

## 用語

- **デイリーゴール**: その日 1 日で達成する成果。プロジェクト、ゴール文、受入条件、
  許可範囲、対応する Actio task を持つ。
- **ゴール候補**: AI や前日の持ち越しから出た案。人間が確定するまでゴールではない。
- **専用セッション**: デイリーゴール 1 件に対して起動する 1 本のセッション。
- **確認 (checkpoint)**: 1 時間ごとに Cc が行う進み具合の確認。
- **証跡**: Cc が機械的に集めた進捗の根拠 (commit、PR とその状態、Actio task の状態変化)。
  セッション自身の自己申告は証跡に数えない。
- **許可範囲**: その日のうちに AI が実行してよい操作 (マージ・テスト・サービス操作・反映)。
  朝の確定時に人間が明示したものだけ。

## 状態の所有者

| 状態 | 所有者 | 備考 |
|---|---|---|
| タスクの内容・状態 | Actio | 進捗の正本。Cc は task ID を参照するだけで書き換えない |
| デイリーゴール (ゴール文・受入条件・許可範囲・確定者) | Cc `daily-goal-run` | 確定した人の Discord/Slack 上の本人性を保存する |
| 専用セッションとの紐付け、確認の記録、停止理由 | Cc `daily-goal-run` | |
| セッション内の自走継続 | Cc `autonomous-continuation` (Goal & Go) | 予算の扱いは下記「予算」 |
| 起動の実体 | Cc `agent-delegation` | 専用テンプレートで spawn する |

## 流れ

### 1. ゴール候補を出す (朝)

- 前日の終わり (確認カードが「達成」「やり切り」になった時点) と朝の起動時刻の前に、
  プロジェクトごとの候補カードを出す。材料は Actio の進行中・期限の近い task と、前日の持ち越し。
- 候補は案である。人間が確定しない候補からセッションを起動しない。
- 人間は候補を選ぶ・書き直す、または候補なしで `/co-daily-goal` から直接書く。

### 2. ゴールを確定する

確定には次のすべてが要る。欠けていれば確定せず、欠けている項目を聞き返す。

- プロジェクト (1 件)
- ゴール文
- 受入条件 (確認で照合できる形。例: 「PR がマージされ、Ex で反映を確認」)
- 対応する Actio task (1 件以上。無ければ確定時に作る)
- 許可範囲 (マージ / テスト / サービス操作 / 反映 のそれぞれ可否。既定はすべて不可)

確定は人間本人の操作だけで成立する。bot・webhook・AI の発言・自由文の推測では確定しない
(sprint-dialogues の CC-SD-02 と同じ本人性の扱い)。

### 3. 専用セッションを起動する

- 起動時刻は **朝 7:30** (設定可)。その時刻までに確定したゴールを 7:30 に起動する。
  7:30 より後に確定したゴールは確定した時点で起動する。
- 起動は `agent-delegation` の専用テンプレート `daily-goal-runner` を使う。
  依頼文にはゴール文・受入条件・許可範囲・Actio task ID だけを入れる。
- 同じデイリーゴールに対する起動は 1 回だけ。依頼の同一性は `daily_goal_id` で持つ。
  起動の結果が不明なときは既存の run とセッションを照合し、見つからない間は再起動しない (CC-INV-03)。
- 作業場所はプロジェクトの規則 (task worktree / direct-main) に従う。

### 4. 確認と確認の間 — Goal & Go で自走

- 専用セッションは Goal & Go が ON。明示ゴールとしてデイリーゴールを渡す。
- セッションはゴールの範囲だけで作業する。Actio の他の未着手 task や git diff の残りを持ち込まない
  (goal-and-go の 2026-10-07 の不変条件と同じ)。
- 許可範囲に無い操作が必要になったら、ask で聞いて止まる。

### 5. 1 時間ごとの確認

Cc が 1 時間ごとに次を行う。

1. 証跡を集める: 前回の確認以降の commit、PR の提出・審査・マージ、Actio task の状態変化。
2. セッションへ確認の inject を送り、受入条件に対する進み具合・次の 1 時間でやること・
   人間判断が要る点を、決まった形で書かせる。
3. デイリーゴールのカード (Discord のスレッドに 1 枚) を同じ message の更新で書き換え、
   タイムラインに 1 行足す。カードには 証跡 / セッションの報告 / 人間判断 を分けて載せる。
4. 進捗を判定する。前回から証跡が 1 件以上増えていれば「進捗あり」、増えていなければ「進捗なし」。
5. **進捗なしでも止めない。** 確認の inject を「完了確認」に切り替え、受入条件と対応する Actio task の
   一つずつについて、完了しているか・残りは何かをセッションに確かめさせる。
   - すべて完了している → 6 の「ゴール到達」の照合へ進む。
   - AI だけで進められる残りがある → その残りを次の 1 時間でやることとして書かせ、続行 (GO) する。
   - 残りがすべて達成不能か人間判断待ち → 6 の「十分にこなした」の照合へ進む。

回答待ちの扱い:

- 未回答の質問があるセッションには確認の inject を送らない (CC-INV-08)。
  カードには「回答待ち」と経過時間だけを出し、催促は 1 回にとどめる。
- 回答待ちの間は予算を消費しない。回答が付いたら次の確認から通常どおり続ける。

### 6. 終わり方

止まる条件は次の 3 つだけ (2026-10-10 neco 指示)。時刻・日付の変わり目・進捗の停滞では止めない。

| 止まる条件 | 照合 | カード |
|---|---|---|
| **ゴールに到達した** | 受入条件の一つずつに対応する証跡 (PR のマージ、反映の確認、Actio task の完了など) がそろっている。セッションの「終わった」だけでは到達にしない | 「達成」 |
| **十分にタスクをこなした** | セッションが残りの一覧を出し、残りの一つずつが「達成不能 (理由付き)」か「人間判断待ち (未回答の質問・人間依頼に対応)」のどちらかである。AI だけで進められる残りが 1 件でもあれば認めず、続行 (GO) を返す | 「やり切り」。残りの一覧と、人間に決めてほしい点を載せる |
| **人間が停止した** | 人間本人の停止操作 | 「停止」 |

止まる条件ではないが、状態として扱うもの:

| 状態 | 動作 |
|---|---|
| セッションの喪失 | 「喪失」と表示し、自動で別セッションを起動しない。再開は人間が選ぶ (UX-CC-S3) |
| 日付が変わった | 止めない。翌朝の候補カードに「継続中」として出し、同じゴールで 2 本目を起動しない |

終了は既存の session-end 手順に合流する。「やり切り」の残りは翌朝の **候補** に入れる。
翌日のゴールには自動でならない。

## 予算

- 時刻による上限は持たない。止まるのは上記の 3 条件だけ。
- 確認と確認の間は、Goal & Go の既存の上限 (人間入力 1 回あたり 6 回・2 時間) をそのまま使う。
- **緩和は 1 つだけ**: 1 時間ごとの確認 (進捗あり、または完了確認で AI だけで進められる残りが
  ある場合) を、Goal & Go の継続回数と時間の予算のリセットとして扱う。人間のゴール確定が
  止まる条件までの続行を許可しているため。回答待ちと、止まる条件に当たった後はリセットしない
  (CC-WM-INV-03 で許す唯一の緩和)。
- 委託 run の起動回数は既存の delegation の上限に従い、緩和しない。

## 不変条件

| ID | 内容 |
|---|---|
| CC-DG-INV-01 | 人間本人が確定したデイリーゴールだけが専用セッションを起動する。候補・AI の発言・経過時間では起動しない |
| CC-DG-INV-02 | デイリーゴール 1 件に専用セッションは同時に 1 本。結果不明の起動は照合し、再送しない |
| CC-DG-INV-03 | 進捗の判定とゴール到達は Cc が集めた証跡だけで行い、セッションの自己申告で進捗あり・到達にしない |
| CC-DG-INV-04 | 許可範囲はゴール確定時に人間が明示したものだけ。確認・自走・ゴール文から許可を足さない |
| CC-DG-INV-05 | 止まるのはゴール到達・十分にこなした・人間の停止の 3 つだけ。進捗なしは完了確認を経て続行する |
| CC-DG-INV-06 | 「十分にこなした」は、残りの一つずつが達成不能 (理由付き) か人間判断待ち (未回答の質問・人間依頼に対応) のときだけ認める |
| CC-DG-INV-07 | 回答待ちの間は確認の inject・自走を送らず、予算を消費しない |
| CC-DG-INV-08 | Actio の task 状態を Cc から直接書き換えない。残りを翌日のゴールへ自動で持ち越さない |

CC-INV-02/03/04/06/08、CC-WM-INV-01〜04 を適用する。

## 他の方式との違い

- **WM-1 対話**: 対話は人間の指示ごとに自走予算が戻る。デイリーゴールは確定 1 回で止まる条件まで進み、
  予算は 1 時間ごとの確認で戻る。
- **WM-5 Director 案件**: 案件は日をまたぎ、分解と委託を工程として追う。デイリーゴールはゴール 1 件に 1 セッションで、
  分解はセッション自身が行う。複数日の仕事は案件にし、その日の分をデイリーゴールとして切り出してよい。
- **WM-7 スプリント (休止)**: 計画・振り返りの会合とフェーズ遷移を持たない。1 日の確定と 1 時間の確認だけ。

## 実装の分割 (後続)

本書は仕様のみ。実装は次の単位で別 PR にする。

1. ドメイン: `src/daily-goal-run/` に確定の検証・進捗判定・終了判定の純関数、
   デイリーゴールと確認記録の永続化、起動と確認の use case。
2. 起動: `daily-goal-runner` テンプレートと spawn 依頼の同一性。
3. 確認: 1 時間ごとの scheduler、証跡の収集 (git / Revisor / Actio)、Goal & Go 予算リセットの連携。
4. 表示: Discord のカードとタイムライン、`/co-daily-goal`、朝の候補カード。
5. 方式の記録: セッション metadata の方式 (CC-WM-INV-01)。

## 受け入れ基準

- [ ] 確定に必要な項目が欠けたゴールは確定せず、欠けた項目を聞き返す。
- [ ] 人間本人の確定だけが専用セッションを起動し、同じゴールで 2 本目が起動しない。
- [ ] 1 時間ごとに証跡・報告・判断点が同じカードの更新で届く。
- [ ] 7:30 までに確定したゴールは 7:30 に、それ以降に確定したゴールは確定時に起動する。
- [ ] 1 時間ごとの確認で Goal & Go の予算が戻り、回答待ちと停止後は戻らない。
- [ ] 進捗なしの確認では完了確認を送り、AI だけで進められる残りがあれば続行する。
- [ ] ゴール到達・十分にこなした・人間の停止の 3 つでだけ止まり、時刻や停滞では止まらない。
- [ ] 「十分にこなした」は、AI だけで進められる残りが 1 件でもあれば認めない。
- [ ] 回答待ちの間は確認と自走を送らず、予算を消費しない。
- [ ] 許可範囲に無い操作をセッションが行わず、聞いて止まる。
- [ ] 「やり切り」の残りは翌朝の候補に出るが、ゴールには自動でならない。
