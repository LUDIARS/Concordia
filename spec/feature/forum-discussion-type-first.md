# 議論タイプと Cc 自動起動の境界

契約: CC-FORUM-TYPE-01。価値: UX-CC-SC-W1 / UX-CC-SC-W3。
所属: chat-platforms（支援境界）。根拠: neco のタイプ決定前の通知抑止と企画/議論でのプロジェクト質問不具合の修正指示。

利用者が議論タイプを選ぶ前に、コード作業用の起動質問やガード所見を出さない。
Discord の appliedTags がタイプ選択の正本であり、Cc はその状態を書き換えない。

- タイプ選択タグを備えるフォーラムでは、一つに決まるまで guard/intake/spawn を保留する。
- 企画/議論はプロジェクトなしの Di 議論。Cc の自動 spawn 対象外とする。
- 改善/議論が一つ選ばれた時だけ既存の認可・guard・project scope・intake を実行する。
- 通常の Cc フォーラムは従来どおり。明示 /spawn の認可は変更しない。
- ThreadUpdate でタイプが起動可能に変われば再入する。実行済み判定と並行イベントの抑止を維持する。

状態所有者は Discord（タイプ）と既存 spawn run（実行同一性）。新しい DB 状態を作らない。
復旧はタグ更新による再入。取得失敗は保留し、未確認のまま起動しない。
テストは同じ変更単位で追加する。session 自身のテスト実行・Cc 再起動は未実施。
