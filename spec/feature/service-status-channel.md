# 子会社別のサービス稼働チャンネル

neco 2026-10-06 の要求と「実装開始」に対応。UX-CC-W1/W4/W5。
進捗の正本は Actio `actio:845a7ca2-d106-49aa-b49e-8b0ceda7516d`。この文書は仕様と検証の根拠でありtask状態を代替しない。
失うと困る状態は、拠点で何が利用可能かを把握できることと、子会社へ非公開運用情報が漏れないこと。
本社は全拠点の稼働中サービスを表示。子会社は本社が指定する拠点とサービスの両方に一致する情報のみ表示。
Discord の状態カテゴリに「サービス稼働」を冪等作成し、現在一覧を更新、変化を履歴投稿する。

## 所有者と不変条件

- CC-SS-01: Ex が監視状態・鮮度を所有。Cc は既存 `/api/v1/federation/mesh` のキャッシュのみ読む。要求に伴う追加 probe/遠隔操作は行わない。
- CC-SS-02: Cc が子会社ごとの拠点許可とサービス選択を所有。本社管理API/画面で設定。未設定・壊れた設定は子会社に一件も公開しない。拠点IDはローカル=`self`、遠隔=`peer:<登録ID>`。表示名を認可キーにしない。
- CC-SS-03: 中央の公開除外ポリシーに登録された拠点・サービスと、本社限定サービスは子会社に非公開。登録repo/コード/サービス名のいずれが該当しても除外する。通知、候補、件数、履歴、状態APIに共通適用し、管理者も子会社設定で禁止対象を許可できない。本社一覧には含む。保護対象の識別子は公開リポジトリへ平文で記録しない。
- CC-SS-04: 観測upかつ拠点接続upかつ観測が新鮮なものだけを稼働一覧へ載せる。古い観測・未観測・切断を稼働/停止と推測しない。未観測/切断は許可された拠点名と状態だけで表示。
- CC-SS-05: 同じサービスは拠点ID+サービスcodeの複合キーで識別し、設定もこの単位で保存する。再起動時も保存済みの直近状態から差分を取る。設定を外したものは停止通知しない。非公開へ変更された過去の管理メッセージは削除/更新して残さない。
- CC-SS-06: 送信結果不明は自動再送しない。次回は保存済みメッセージID/イベントマーカーで照合。不明のままなら当該チャンネルを停止し運用ログに記録。送信はmention無効。停止はtimerを解放し、進行中処理も停止フラグを確認する。

## 構成

支援ドメイン `service-status`: 純関数の認可・状態射影、Exキャッシュクライアント、設定永続化、Discord投影ユースケース。
`chat-platforms`: Discord transport とチャンネル確保。既存 core の協調に運用可視性を提供し、coreそのものとは呼ばない。
本社管理の子会社編集パネルで許可拠点のチェックボックス、選択拠点に存在する公開可能サービスのチェックボックスを提供。
設定変更は次の更新（通常60秒以内）で反映し、過去の当該チャンネル管理投稿も削除する。Discordの削除失敗や結果不明送信が照合不能なら新しい投稿を止め、管理者による照合・削除が必要。利用者の転載・引用は管理対象外。Ex不通時は以前の稼働一覧を未確認表示へ置換する。

## 検証と復旧

回帰テストを同じ変更単位に登録。ユーザー許可は作成のみで、実行/起動/再起動は未許可。
復旧は本PRのrevertと、許可された別操作による配備。既存Ex監視、他通知設定、secret、catalogは変更しない。
revertだけではDiscord投稿を撤去しない。復旧時には当該チャンネルの管理投稿を照合し、別途許可された管理操作で撤去または「更新停止」と明示する。結果不明送信の復旧では保存済みnonceとBot投稿を照合してからledgerを修復し、未照合のpendingを単に消して再送しない。
初期の子会社拠点/サービス割当は空。人間が管理画面で選択後に通知を開始する。
表示対象はEx meshでcoveredかつ新鮮なhealth=upのサービス。プロセスの存在だけから稼働を推測しない。
