# チーム相談のファシリテーション

Actio `actio:7a5c833d-c293-4394-9ac8-62335f48ffa0`

UX-CC-W4/W5、UX-CC-S3/S5/S6。チームの企画が進んだとき、相談した場所で追加・変更・取り下げ・決定・未決の論点を確認できる。

## 所有と契約

- CC-TEAM-DISCUSSION-02 (CC-INV-02/03)。論理 runtime が所有する登録済み相談面と公開スレッドで、収集済みの人間の本文をチャンネル別に扱う。履歴回収とライブ受信は同じ収集経路を通る。履歴回収中は判定を保留する。Bot、webhook、システム投稿、非公開スレッドを除外する。Notion 転記は従来の経路を通る。
- CC-TEAM-DISCUSSION-03 (CC-INV-03/04/07)。最後の投稿から5分経過し、未判定の投稿があれば、SQLite に同じチャンネルと範囲の判定を一度だけ確保する。現在の企画要約と未処理投稿を Claude の会話専用経路に渡す。差分ありの場合、共有する差分と次回用の企画全体の要約を検証して保存する。差分なしは判定済み位置だけを記録する。プロンプト本文のコスト台帳への保存は無効にする。実行・テスト・サービス操作・DB変更・push・merge・人間の決定の代行を禁止し、未決事項と決定を分ける。
- CC-TEAM-DISCUSSION-04 (CC-INV-04/06/07)。差分を元のチャンネルへメンション通知なしで投稿する。各2000字以下の分割の受領 ID を保持し、全分割の受領時だけ企画要約と配信済み位置を更新する。差分なし、生成異常と停止中の生成は Discord に投稿しない。

## 復旧と検証

停止時は新規判定と新規配信を止め、生成を中断し、進行中の処理から得た結果と受領 ID を保存してから終了する。再起動で実行中だった生成は失敗に、結果のない配信試行は結果不明にする。保存済みで未送信の分割は続行できる。生成失敗時は後続の人間投稿があれば新しい範囲で未処理分を再評価する。結果不明や途中まで配信された範囲は自動再送せず、運用担当が Discord 投稿と台帳を照合するまで該当チャンネルを保留する。取り消す場合は実装を戻し、調査資料として台帳を保持する。

既存の収集行は履歴回収時に取得元の guild・相談面・投稿時刻を補う。チームの履歴回収に失敗した場合はログを残し、履歴を回収できるようになるまでそのチームの判定を保留する。

単体テストで静穏期間、収集対象、履歴回収、判定範囲の冪等性、差分なし、失敗・停止・配信不明、分割の受領を確認する。
