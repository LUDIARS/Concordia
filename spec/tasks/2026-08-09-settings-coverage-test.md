# 未露出の設定を検出する回帰テスト (W5-4)

## 目的

**W5 で一番重要な成果物**。 「また WebUI に出ていない設定が増える」 のを構造的に止める。
DB 設定キーの定数と env 名の一覧を走査し、 レジストリに登録されていないキーがあればテストを落とす。

これが無いと W5-1〜3 は一度きりの棚卸しで終わり、 同じ問題が再発する。

前提: `2026-08-09-settings-registry-core.md`。

## 完了条件

- DB 設定キー定数と env 名の一覧を走査してレジストリと突き合わせるテストがある。
- レジストリ未登録のキーが 1 つでもあればテストが**落ちる**。
- **落ちることを実際に確認する**: レジストリから 1 項目を一時的に外してテストが赤になるのを見て、
  その結果を PR 説明に書く (テストが実は何も検出していない、 を防ぐ)。
- 意図的に対象外とするキー (テスト専用の `VITEST` / `NODE_ENV` 等) は
  **明示的な除外リスト**として理由付きで持つ。 正規表現で暗黙に取りこぼさない。
- 並行 PR が後から足すワークフロー有効化フラグ (`workflow.*`) を追加した時に、
  レジストリ未登録ならこのテストが落ちること (= 後続 PR への網になっている)。

## スコープ (編集可ディレクトリ)

- `tests/`
- `src/config/` (走査対象となるキー一覧のエクスポートが必要な場合のみ)
- `spec/tasks/` (この md)

## 設計上の注意

- 走査は静的に行う (ソースを読む / 定数配列を読む) 。 実行時 `process.env` の
  スナップショットを見る方式にしない — 未設定のキーが検出できなくなる。
- 除外リストが肥大したら 「レジストリに足すべき設定」 を除外で誤魔化していないか点検する。
