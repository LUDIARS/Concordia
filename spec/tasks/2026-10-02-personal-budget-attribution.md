# 個人の AI 予算 C — 全体の停止を子会社にも効かせる、委託の子へ依頼者を引き継ぐ

設計正本: `spec/feature/personal-ai-budget.md` §3 (`SPEC-PBUDGET-CONSUME`)。価値 UX-CC-W8 / シナリオ UX-CC-S9。
ドメイン `personal-ai-budget` (支援)、委託の起動は agent-delegation。前提: `2026-10-02-personal-budget-core` がマージ済み。
2026-10-02 neco 指示 (個人の AI 予算 A の実装で分かった現状への対応として選択):「全体の停止を子会社にも効かせる」
「委託の子へ依頼者を引き継ぐ」。「受付チャンネル経由も帰属させる」は選ばれていないので、本タスクでは扱わない。

## 背景 (A の実装で分かった現状)

- 子会社の受付 (`evaluateSubsidiaryRequest`) は、導入前から全体の日次 budget を見ていない。A は現状を変えないことを優先し、
  全体の超過で止めるのを「個人の予算が効いている人」だけにした。その結果、報酬分を持つ人だけが全体の超過で止まり、
  持たない人は通る (CC-PBUDGET-INV-03 の意図と逆転している)。
- `/v1/delegation/invoke` は body の `requester_discord_user_id` だけを使い、親セッションの依頼者を引き継がない。
  委託された子セッションの消費は個人へ帰属しない。

## 目的

全体の日次 budget (停止スイッチ) を、子会社の受付でも全員に効かせる。委託された子セッションの消費を、親の依頼者の
月間分・報酬分から引けるようにする。

## 完了条件

- [ ] 子会社の受付で、全体の日次 budget が超過中なら全員を止める (個人の予算が効いているかに関わらない)。
      `decideDispatch` の「全体 超過 → 止める」を個人の有無より先に判定する (設計書 §3 の表の 1 行目のとおり)。
- [ ] 止めた理由 (全体が上限) を依頼者へ返し、監査記録に残す。残高の数字は共有チャンネルへ出さない (CC-PBUDGET-INV-08)。
- [ ] A で固定した「月間分の上限が 0 の個人では現状の払い出しの動きが変わらない」のテストを、「全体が超過していない限り変わらない」へ
      書き換える。契約 pbudget-C-3 も合わせる。
- [ ] `/v1/delegation/invoke` が `parent_session_id` を持ち、body に依頼者の指定が無いとき、親セッションの依頼者と所属会社を
      子セッションへ引き継ぐ。body に依頼者の指定があればそれを優先する。親に依頼者が無ければ引き継がない (子も依頼者なし)。
- [ ] 引き継いだ依頼者で、起動通知などのメンションが新たに飛ばないこと。引き継ぎは消費の帰属 (と、バグ報告の受取人の解決) にだけ使う。
      メンションに使う値と帰属に使う値が同じ列で分けられない場合は、実装せず報告する。
- [ ] 孫以降の委託も同じ規則で引き継ぐ (親の値をそのまま渡すだけで、遡って探索しない)。
- [ ] 引き継いだ子の消費が、親の依頼者の月間分 → 報酬分の順で引かれることを結合テストで固定する。
- [ ] 設計書 `spec/feature/personal-ai-budget.md` の §3 と §9 を実装に合わせて直す (全体の停止の適用範囲、依頼者の引き継ぎ)。
- [ ] 単体・結合テストを同じ変更で書き、`cc.acceptance.json` に対応付ける。実行は指示があるまでしない。

## 本タスクで扱わないもの

- 受付チャンネル経由の依頼の帰属、`/consult` と `/v1/admin/spawn-session` への個人の判定の適用。
- 委託の起動そのものを個人の予算で止めること (今は委託の起動はどの budget も見ていない)。必要なら別途判断する。
