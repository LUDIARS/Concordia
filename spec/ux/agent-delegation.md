# 作業委任の UX

## 誰の、どの状況の問題か

本社・子会社の担当者や親セッションが、具体的な仕事を適切な AI に任せたい場面を扱う。
依頼を投稿しただけで実際には起動していない、親の停止で子との関係が消える、同じ依頼を
出し直して複数の子が編集する、といった問題を避けたい。

例：依頼者が「Cc のレビュー指摘 1〜5 を Sol に修正してほしい」と伝えた時、対象・範囲・
モデル・許可された完了範囲を保ち、待ち行列に入った段階と実際の起動を区別して知らせる。

## このプロダクトが何を解決するか

[プロダクト UX](product.md) の UX-CC-W2/W3/W5 に貢献する。一度渡した依頼について、
担当する実行と成果まで辿れるようにし、依頼者が子セッションを手で監視し続ける負担を減らす。

コアとする分類案の理由は、異なる AI・組織範囲へ意図を保って仕事を渡し、戻った成果を
同じ依頼へ結び付けることが Cc の主要な差別化だからである。モデル API・起動 CLI・
外部の審査器の内部実装は所有しない。

## どの価値を実現するか

| 価値 ID | 利用者に起きる望ましい変化 | 判断方法・条件 | 証拠 | 現状 |
|---|---|---|---|---|
| UX-CC-AD-W1 | 依頼した対象・モデル・範囲で仕事が始まる | 本社/子会社の依頼について受付と起動を区別し、権限外の対象を起動しない | UX-CC-S1/S2、CC-INV-01/02 | 未測定 |
| UX-CC-AD-W2 | 中断や再送で同じ仕事を重複して任せない | 受付、起動要求、応答、結果保存の間の中断で同じ依頼を照合し、結果不明は明示する | UX-CC-S2/S3/S6、CC-INV-03/07 | 未測定 |
| UX-CC-AD-W3 | 成果の状態を確かめてから次の判断へ進める | 子の終了だけで成果完成とせず、PR 提出・審査・公開・差戻しを辿れる | UX-CC-S4、CC-INV-04/05 | 未測定 |

依頼者とレビュー担当が評価する。判断基準は依頼を出し直す前に現状と次の行動を確認できること。
中断時の重複件数や復旧時間は、承認された検証で対象版とシナリオを記録して測定する。現時点では未測定。

## 主要シナリオと失敗からの回復

- **AD-S1 委任受付**：親または人間が範囲を指定 → 対象と起動条件を確認 → 待機か起動を提示 → 担当 run と子 session を追跡する。モデル指定はカタログと照合し、不足する対象情報は確認する。
- **AD-S2 Issue からの受付**：対象プロジェクトの Issue に運用ラベル → 起票者/ラベル付与者の認可 → 承認待ちまたは委任 → 同じ Issue から成果へ辿る。承認待ちは承認した本文・対象を保ち、再起動で捨てない。
- **AD-S3 応答喪失と復旧**：起動の応答が途切れる → 依頼台帳を開く → 同じ依頼の既存実行を照合 → 再開または結果不明の確認へ進む。起動した可能性がある仕事を無条件で再実行しない。
- **AD-S4 成果返却**：子が実装を終える → 対象の PR を提出 → 審査状態と成果リンクを返す → 依頼者が次の判断を行う。子の終了・審査通過・公開・マージは別の事実として扱う。
- **AD-S5 実行主体の交代**：ワーカー停止/lease 喪失 → 新しい払い出しを止める → 進行中の起動結果を確定または確認待ちにする → 後続主体が同じ台帳から継続する。

## 守る制約と優先順位

同一依頼と権限を保つことを、即時起動より優先する。依頼・起動・結果保存の境界では
永続状態を根拠に判断し、結果不明を成功や未起動へ変換しない。停止時にも実行結果の保存先を
先に閉じない。外部 Issue は資料であり、依頼経路の権限やテスト・マージ方針を上書きできない。

## 対応関係・非目標・未決事項

| 価値 | シナリオ | 不変条件 | 対応する既存仕様 |
|---|---|---|---|
| UX-CC-AD-W1 | AD-S1/AD-S2 | CC-INV-01/02 | [delegation](../feature/delegation.md)、[subsidiary](../feature/subsidiary-delegation.md) |
| UX-CC-AD-W2 | AD-S3/AD-S5 | CC-INV-03/07 | [queue](../feature/delegation-coordination.md)、[Issue Workflow](../feature/github-issue-workflow.md) |
| UX-CC-AD-W3 | AD-S4 | CC-INV-04/05 | [local PR](../feature/revisor-local-pr-submission.md) |

不変条件 ID は [DDD 方針](../architecture/ddd.md) で定義する。delegation-queue / delegation-launch は
既存の実行責務、github-issue-workflow / revisor-local-pr は外部境界の責務として連携する。
審査結果の内容は Revisor が所有する。Cc が審査通過を捏造したり、別ブランチの結果を使ったりしない。

非目標は AI が生成したコードの無条件な正しさの保証と、依頼範囲外の自動マージ。
結果不明時の確認導線・待機時間の目標は運用担当とプロダクト責任者が決める。
